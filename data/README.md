# Data — Volleyball Spike Clips

This directory holds the raw video clips, their annotations, and any derived caches. Most of the bulk (the `.mp4` files) is **not** stored in git; the pipeline is designed to regenerate everything else on demand.

---

## 1. Layout

```text
data/
├── README.md                      ← this file
├── spike_clips/                   ← raw .mp4 clips (NOT in git)
│   ├── V1.mp4
│   ├── V2.mp4
│   └── ...                        (V1..V20)
├── labels/
│   └── contact_frames.csv         ← required: one row per video, ground-truth contact frame
└── processed/                     ← regenerable; safe to delete
    ├── dataset_windows.csv        ← built by src/build_dataset.py
    └── features/
        ├── pose/<video>.csv       ← cached MediaPipe wrist kinematics (src/features_pose.py)
        └── audio/<video>.csv      ← cached librosa RMS + onset (src/features_audio.py)
```

## 2. Getting the videos

The raw clips are short attack footage (≈3–8 s each, 30–60 fps) collected from practice and game video. They are not redistributed inside this repository because of size and source-rights considerations.

To populate `data/spike_clips/`:

- **Use the bundled labels with your own clips.** The shipped `labels/contact_frames.csv` references files named `V1.mp4 .. V20.mp4`. If you already have these clips, drop them into `data/spike_clips/` and the rest of the pipeline will work as-is.
- **Use a different video set.** Place arbitrary `.mp4` clips in `data/spike_clips/` and re-create `labels/contact_frames.csv` (see §3) with one row per video. Filenames in `video_name` must match exactly. The pipeline does not care about FPS or resolution as long as `total_frames` is honest.
- **Request the original bundle.** Email the author (see top-level `README.md`) for a downloadable archive of the 20 clips referenced by the shipped labels.

The minimum useful dataset is **two** clips (LOO needs `N ≥ 2`). With fewer than ~10 clips, expect very high LOO variance.

## 3. Label file: `labels/contact_frames.csv`

**Required columns** (header row, comma-separated):

| Column | Type | Meaning |
|---|---|---|
| `video_name` | string | Filename inside `data/spike_clips/`, e.g. `V3.mp4`. Must match exactly (case-sensitive on Linux). |
| `contact_frame` | int | 0-indexed frame number where the ball makes contact with the hand. |
| `fps` | float | Frame rate of the clip (used by the audio resampler in `features_audio.py`). |
| `total_frames` | int | Total decodable frame count. Used to validate `(t-1, t, t+1)` windows. |

The shipped `labels/contact_frames.csv` already covers `V1..V20`.

### 3.1 Annotating new clips interactively

Use the bundled tool from the project root:

```bash
python annotate_contact.py            # walks through clips not yet in the CSV
python annotate_contact.py --all      # re-annotate every clip (overwrites existing rows)
```

Controls during playback:

- `a` / `d` — previous / next frame
- `s` — save the current frame as `contact_frame` and move on
- `q` — skip this video (existing CSV row is kept if any)

The tool **merges** with any existing CSV so you do not lose previous labels.

## 4. Derived files (`data/processed/`)

These are regenerated by the scripts in `src/` and can be deleted at any time:

| File | Generator | Cost |
|---|---|---|
| `processed/dataset_windows.csv` | `src/build_dataset.py` | Seconds |
| `processed/features/pose/<video>.csv` | `src/features_pose.py` | ~10–60 s per video (MediaPipe) |
| `processed/features/audio/<video>.csv` | `src/features_audio.py` | ~1–5 s per video (librosa) |

Pose and audio extraction are cached: re-running the script over an already-processed video is a no-op unless you pass `--overwrite`.

## 5. Known gotchas

- **`fps` mismatch:** OpenCV's `CAP_PROP_FRAME_COUNT` and `CAP_PROP_FPS` can disagree with the actual decoded length. `src/build_dataset.py` therefore counts frames by decoding rather than trusting the metadata. If you see "skipped video: too few frames" warnings, double-check the file is not corrupt.
- **Audio missing:** clips without an audio track will fail `src/features_audio.py`. Fix with `ffmpeg -i in.mp4 -c:v copy -an out.mp4` to confirm, then re-record or strip the audio path entirely.
- **Filename case:** Linux is case-sensitive. `V3.MP4` and `V3.mp4` are different files; the labels file uses lowercase `.mp4`.

## 6. Privacy / source notes

The shipped clips depict consenting amateur volleyball players in practice / game settings. If you record new clips, ensure you have the right to use the footage for academic / personal analysis before adding it to this dataset.
